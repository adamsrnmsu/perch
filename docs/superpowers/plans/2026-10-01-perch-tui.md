# perch tui: implementation plan

Spec: `docs/superpowers/specs/2026-10-01-perch-tui-design.md`. Bead: perch-s7p.

Tests are plain `def` functions that drive `App.run_test()` through
`asyncio.run`, so perch needs no pytest-asyncio.

## Task 1: the projects table

- `perch/tui.py`: `row(home, name)` gives the cells for one project: name,
  gitlab_project, stoplight and headroom (the latest `team` row in
  history.jsonl), the dump and weekly.csv ages (`doctor.freshness`), and the
  watch flag count. A config that fails to load gives an error row.
  `PerchTUI(home)` composes a `DataTable`, a `Log`, a hidden `Input` and a
  `Footer`.
- Tests (`perch/tests/test_tui.py`): every project renders; a history row the
  test writes shows as `YELLOW` and `$12,345`; no history and thin history
  show "—"; a watch with one flag shows `1`; a malformed perch.yaml is an
  error row.

## Task 2: keys run commands

- `_spawn(argv, cwd)` streams a subprocess's lines; `b m a d f w Q` build
  `perch <command> -p <name>` (`a` is `perch monday --all`), run it in a
  thread worker, write each line prefixed with the project to the `Log`, then
  refresh the table. A key while one runs writes `busy: <action>`.
- Tests: each key's argv with `_spawn` faked; the cursor moving down changes
  the project, across a refresh; busy.

## Task 3: `c`, `h`, `r`, `?`, `q`

- `c` shows the `Input`; enter splits it with `shlex` and runs `perch cut`.
- `h` runs `steps.hours` inside `App.suspend()`, then refreshes.
- Tests: the cut flags pass through; `h` with suspend and the editor faked
  runs `$EDITOR weekly.csv` and the table shows the history row written
  meanwhile.

## Task 4: wiring and docs

- `perch/cli.py`: append the `tui` command. `pyproject.toml`: `textual`.
- README command list, CLAUDE.md architecture line, the spec's "Changes
  during build".
